API contract

POST /api/games { playerColor: "white" | "black" }
GET /api/games/:id → { fen, turn, status, history, legalMoves, ... }
POST /api/games/:id/moves { from: "e2", to: "e4", promotion?: "q" }

Algorithm

  1. Use chess.js as the authoritative rules engine.
  2. Return a complete snapshot after every accepted move.
  3. Poll GET /api/games/:id every 1.5 seconds for external agent moves.

UI layout

  1. Board: select source and highlighted legal destination.
  2. Move rail: turn state, SAN history, demo Jev action.
  3. API dialog: game ID and copyable commands.

Decisions

IDChoice · Rationale
D-001Build chess, not blackjack. The request repeats chess in both concrete deliverables.
D-002Expose legal moves and FEN. Agents can operate without scraping UI state.
D-003Keep games in memory. This first playable slice needs no database.

Tradeoffs

IDPicked over Rejected · Reason
T-001chess.js over custom rules. Correct castling, promotion, en passant, and terminal states.
T-002Polling over WebSockets. One external opponent does not justify persistent transport.

Assumptions

Reversibility

R-001 · medium. Delete the additive app; no durable data or external side effects exist.

Definition of done

  • Legal human moves update the browser.
  • External HTTP moves appear through polling.
  • Illegal moves return 422.
  • Desktop and mobile layouts remain usable.
